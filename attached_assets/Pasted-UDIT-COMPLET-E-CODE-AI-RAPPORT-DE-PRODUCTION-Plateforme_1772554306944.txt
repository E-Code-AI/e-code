SECTION 1 — FAILLES DE SECURITE CRITIQUES (BLOCKER)

Fichier : .replit ligne 75
Probleme : La clé sk_test_51QPg0B... est en clair dans le fichier .replit qui est committé dans Git. Même une clé de test peut être utilisée pour créer des charges frauduleuses.
Solution :
Supprimer immédiatement la ligne TESTING_STRIPE_SECRET_KEY de .replit
Révoquer cette clé dans le Dashboard Stripe (Developers > API keys > Roll key)

Ajouter .replit au .gitignore ou auditer son contenu avant chaque commit

Probleme : VITE_STRIPE_PUBLIC_KEY = "pk_live_51QPg0B..." — bien que les clés publiques soient moins sensibles, exposer la clé LIVE dans un fichier versionné révèle votre account ID Stripe.
Solution : Déplacer dans les Replit Secrets et référencer via process.env.VITE_STRIPE_PUBLIC_KEY
1.3 UTILISATION DE VM2 (VULNÉRABLE)
Fichiers : server/deployment/ab-testing-service.ts, server/utils/secure-sandbox.ts
Probleme : vm2 est officiellement abandonné et a des vulnérabilités d'évasion de sandbox connues (CVE-2023-37466, CVE-2023-37903). Il permet l'exécution de code arbitraire.

1.4 dangerouslySetInnerHTML SANS SANITISATION
Fichiers :

client/src/components/ide/ConsolePanel.tsx

SECTION 2 — BACKEND : PROBLÈMES ET SOLUTIONS
2.1 FICHIER storage.ts MONOLITHIQUE (194 946 octets)
Fichier : server/storage.ts — ~5000+ lignes
Probleme : Ce fichier concentre TOUTE la logique de stockage. C'est un risque majeur de maintenance et de performance (time-to-first-byte, compilation).
Solution : Splitter en modules par domaine :
storage/user-storage.ts

Garder storage/index.ts comme facade qui réexporte l'interface IStorage
2.2 INSTANCIATION STRIPE DUPLIQUÉE (9 FICHIERS)
Fichiers : 9 fichiers différents créent leur propre instance new Stripe()
Probleme : Connexions multiples, inconsistance de versions API, risque de fuite mémoire
Solution : Créer un singleton server/lib/stripe-client.ts :
import Stripe from 'stripe';
let instance: Stripe | null = null;
export function getStripe(): Stripe {
  if (!instance) {
    instance = new Stripe(process.env.STRIPE_SECRET_KEY!, { apiVersion: '2025-08-27.basil' });
  }
  return instance;
}

2.5 TERMINAL WebSocket — EXÉCUTION DIRECTE DE COMMANDES
Fichier : server/terminal.ts
Probleme : Le terminal exécute des commandes dans le processus Node.js via spawn. En production multi-utilisateur, cela signifie que TOUS les utilisateurs partagent le même système de fichiers et les mêmes permissions.
Solution :
Chaque session terminal DOIT s'exécuter dans un container Docker isolé (utiliser ContainerExecutor)
Implémenter le namespace/cgroup pour chaque session
Limiter les ressources (CPU, mémoire, disque) par utilisateur/plan

if (process.env.ALLOW_INSECURE_LOCAL_PTY === 'true' && process.env.NODE_ENV === 'production') {
  throw new Error('FATAL: ALLOW_INSECURE_LOCAL_PTY cannot be true in production');
}

2.7 SESSION STORE — MEMORY STORE EN FALLBACK
Fichier : server/storage.ts — import de memorystore
Probleme : Si la connexion PostgreSQL échoue, le fallback à memorystore signifie perte de sessions au redémarrage et fuite mémoire en production.
Solution : En production, NE JAMAIS utiliser memorystore. Si PostgreSQL est down, le serveur doit renvoyer 503, pas basculer sur un store mémoire.
2.8 hashPassword UTILISE SCRYPT AU LIEU DE BCRYPT
Fichier : server/auth.ts:19
Probleme : La fonction hashPassword utilise scrypt alors que comparePasswords supporte bcrypt. Les nouveaux mots de passe sont hashés avec scrypt mais vous avez bcrypt dans les dépendances.
Solution : Migrer hashPassword vers bcrypt pour la cohérence :
import bcrypt from 'bcrypt';
export async function hashPassword(password: string) {
  return bcrypt.hash(password, 12);
}

2.9 ABSENCE DE WEBHOOK STRIPE SÉCURISÉ
Fichier : server/middleware/csrf.ts ligne 24
Probleme : Le path /api/webhooks/stripe est exclu du CSRF mais aucune vérification de signature Stripe (stripe.webhooks.constructEvent()) n'est garantie dans tous les endpoints de paiement.
Solution : Vérifier que CHAQUE route webhook Stripe utilise stripe.webhooks.constructEvent(rawBody, sig, endpointSecret) et rejette les requêtes sans signature valide.
