### PROBLÈME W-C3: Command injection mobile WS

**Fichier:** `/server/websocket/mobile-websocket.ts` lignes 94-112

**Code actuel:**

```typescript

const cmd = command.split(' ')[0];

if (!safeCommands.includes(cmd)) return;

// Bypass: "ls && rm -rf /"

```

**Solution:**

```typescript

import { spawn } from 'child_process';

const [cmd, ...args] = command.split(' ');

if (!safeCommands.includes(cmd)) return;

spawn(cmd, args, { shell: false }); // Pas de shell!

```

## 6.2 HAUTE PRIORITÉ (17)

 

### PROBLÈME W-H1 à W-H4: No rate limiting

- collaborative-editing-ws.ts lignes 245-263 (cursor updates)

- checkpoint-ws.ts lignes 196-206 (subscriptions)

- monitoring-ws.ts lignes 155-157 (metrics requests)

- collaboration-server.ts lignes 125-180 (all messages)

 

**Solution:** Implémenter throttling per-client (100-200ms)

 

---

 

### PROBLÈME W-H5 à W-H8: Memory leaks

- connections Map jamais nettoyé (collaborative-editing-ws.ts lignes 24, 143, 319)

- monitoring clients Map (monitoring-ws.ts lignes 24, 61, 79-86)

- Yjs documents non cleanup (collaboration-server.ts lignes 365-367)

- Double cleanup interval (collaborative-editing.ts lignes 76-80)

 

**Solution:** Cleanup sur tous les error paths, utiliser singleton pattern

 

---

 

### PROBLÈME W-H9 à W-H12: No message size validation

- collaborative-editing-ws.ts (no maxPayload)

- checkpoint-ws.ts (no maxPayload)

- background-testing-ws.ts (no maxPayload)

- collaboration-server.ts (no validation)

 

**Solution:**

```typescript

const wss = new WebSocketServer({

  maxPayload: 10 * 1024 * 1024 // 10MB max

});

```
