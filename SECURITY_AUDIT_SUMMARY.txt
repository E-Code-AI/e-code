1. SERVER/TERMINAL.TS
================================================================================
Status: ⚠️ CRITICAL VULNERABILITY

Location: Lines 46-55 (connection handler)

Current Implementation:
  wss.on('connection', async (ws, req) => {
    const url = new URL(req.url || '', `http://${req.headers.host}`);
    const projectId = url.searchParams.get('projectId') || '';
    
    if (!projectId) {
      ws.close(1008, 'Missing or invalid projectId');
      return;
    }
    // ⚠️ CONNECTION ACCEPTED - NO AUTH!
  });

Security Gaps:
  ✗ NO JWT verification
  ✗ NO user validation
  ✗ NO authentication token required
  ✗ NO access control check
  ✗ Only checks if projectId exists (not ownership)

Attack Scenario:
  1. Attacker discovers projectId (public, logs, URL)
  2. Connects: ws://app.com/api/terminal/ws?projectId=12345
  3. Connection ACCEPTED without any authentication
  4. Sends: { "type": "input", "data": "rm -rf /" }
  5. Command executes with FULL USER PRIVILEGES

Risk Level: CRITICAL
  - Severity: CRITICAL
  - Exploitability: VERY HIGH (trivial to exploit)
  - Impact: Remote Code Execution (RCE) on user's project
  - Affected Operations: Terminal command execution (lines 126-282)

Recommendation:
  ADD JWT VERIFICATION AT CONNECTION TIME
  - Extract token from query parameters
  - Verify JWT signature
  - Validate user exists in database
  - Check user owns the project
  - Only then accept the connection

Priority: IMMEDIATE FIX REQUIRED

3. SERVER/WEBSOCKET/COLLABORATIVE-EDITING-WS.TS
================================================================================
Status: ⚠️ SECURITY GAP - Message-Level Auth (not Connection-Level)

Location: Lines 106-152 (connection handler), Lines 179-204 (message handler)

Current Implementation:
  private async handleConnection(ws, request) {
    ws.lastActivity = new Date();
    // ⚠️ NO AUTH CHECK - connection accepted immediately
    
    ws.on('message', async (message) => {
      const msg = JSON.parse(message.toString());
      // ⚠️ Message passed to handler without auth verification
      await this.handleMessage(ws, msg);
    });
  }
  
  private async handleMessage(ws, message) {
    switch (message.type) {
      case 'auth':
        await this.handleAuth(ws, message.data);  // ⚠️ Auth in message!
        break;
      case 'join-session':
        await this.handleJoinSession(ws, message.data);  // ⚠️ Before auth?
        break;
      case 'document-update':
        await this.handleDocumentUpdate(ws, message.data);  // ⚠️ Before auth?
        break;
      // ... other message types
    }
  }

Security Issues:
  ✗ No connection-level authentication
  ✗ Authentication deferred to message handler
  ✗ Client MUST send 'auth' message first (protocol requirement, not enforced)
  ✗ No guarantee 'auth' is first message received
  ✗ Unauthenticated clients can connect and receive heartbeat pings
  ✗ No timeout if auth doesn't arrive

Current Protections (Defensive but reactive):
  ✓ handleJoinSession checks if (!ws.userId) → rejects
  ✓ handleDocumentUpdate checks if (!ws.sessionId || !ws.userId) → rejects
  ✓ handleCursorUpdate checks if (!ws.sessionId || !ws.userId) → returns
  ✓ handleSelectionUpdate checks if (!ws.sessionId || !ws.userId) → returns
  ✓ handleRequestState checks if (!ws.sessionId) → rejects

Assessment:
  The code HAS secondary safety checks, so exploitation is harder.
  However, this is a REACTIVE pattern, not PROACTIVE.
  Best practice is to enforce auth at connection level.

Risk Level: HIGH (with secondary protections)
  - Severity: HIGH
  - Exploitability: MEDIUM (defensive checks present)
  - Impact: Could bypass message handlers if checks removed
  - Pattern: Anti-pattern for authentication architecture

Recommendation:
  REFACTOR TO CONNECTION-LEVEL AUTHENTICATION
  
  Option A (Preferred): Extract token from handshake URL
    - Add token to WebSocket URL query params
    - Verify JWT at connection time
    - Only attach message handlers if auth succeeds
  
  Option B: Add auth timeout
    - Set 5-second timeout for 'auth' message
    - Close connection if auth doesn't arrive
    - Enforce 'auth' must be first message

Priority: HIGH - Should be fixed before deploying new features

// For raw WebSocket with token in URL:
wss.on('connection', async (ws, req) => {
  try {
    // Step 1: Extract token
    const token = new URL(req.url!, `http://${req.headers.host}`)
      .searchParams.get('token');
    
    // Step 2: Reject if no token
    if (!token) {
      ws.close(4001, 'Authentication required');
      return;
    }
    
    // Step 3: Verify JWT
    let decoded;
    try {
      decoded = jwt.verify(token, process.env.JWT_SECRET!);
    } catch (error) {
      ws.close(4002, 'Invalid token');
      return;
    }
    
    // Step 4: Validate user
    const user = await storage.getUser(decoded.userId);
    if (!user) {
      ws.close(4003, 'User not found');
      return;
    }
    
    // Step 5: Attach user and accept
    (ws as any).userId = user.id;
    (ws as any).username = user.username;
    
    // Step 6: NOW attach message handlers
    ws.on('message', async (message) => {
      // All messages guaranteed from authenticated user
    });
    
  } catch (error) {
    ws.close(1011, 'Error');
  }
});
