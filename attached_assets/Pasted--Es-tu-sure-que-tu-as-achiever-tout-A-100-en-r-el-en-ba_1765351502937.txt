Tu es un designer UI/UX et un développeur front + backend pour un IDE mobile.
Je veux que tu reproduises au plus proche le design de l’onglet « Shell » de l’IDE montré sur mes captures d’écran (terminal intégré sur mobile).

Objectif : générer la maquette + le code de l’écran “Shell” en version mobile, avec une apparence très similaire et un vrai fonctionnement connecté à un backend (pas seulement du fake front).

1. Style global
	•	Thème clair, fond blanc/gris très pâle.
	•	Design minimal, beaucoup d’espace blanc.
	•	Typo type iOS/Android système, texte fin.
	•	Interface pensée d’abord pour mobile portrait.

2. Zone principale “Shell”
	•	En haut : barre avec le chemin ~/workspace en bleu, puis le prompt $ en noir.
	•	La zone du terminal est un grand panneau blanc qui occupe presque tout l’écran, avec le curseur à la ligne après ~/workspace$.
	•	Police monospace.
	•	Le contenu du terminal doit venir en temps réel du backend, comme un vrai shell (entrée utilisateur → backend → réponse streamée).

3. Barre supérieure de l’onglet
	•	Icône de retour (chevron) à gauche.
	•	Titre centré : “Shell”.
	•	Menu “kebab” (3 points verticaux) à droite ouvrant un panneau “Shell” avec :
	•	Clear Shell → vide l’historique côté front et côté backend (reset de la session).
	•	Find in Shell
	•	Close tab → ferme la vue shell / session côté backend.
	•	Ce panneau apparaît en bottom sheet depuis le bas.

4. Barre de contexte du shell
Sous le titre “Shell”, ajouter une barre horizontale avec :
	•	À gauche : ~/workspace: bash.
	•	À droite : icônes search, trash, close (X) et le texte “Generate”.
	•	Quand on tape sur “Generate”, une barre d’entrée s’affiche en bas du terminal avec :
	•	Placeholder : “Enter a prompt to generate a shell command”.
	•	Bouton/texte “Generate with Assistant”.
	•	Info : “Esc to close, Enter to submit” + bouton “send”.
	•	Le bouton “Generate with Assistant” doit appeler une API backend d’IA qui renvoie une commande shell proposée, puis l’insérer dans le terminal (avec possibilité de l’exécuter).

5. Fonction “Find in Shell”
	•	Quand l’utilisateur choisit “Find in Shell”, afficher une barre sous le chemin avec :
	•	Champ de texte “Find”.
	•	Boutons : Next, Previous, Exit.
	•	La recherche se fait sur l’historique réel du terminal (contenu obtenu depuis le backend ou stocké localement).

6. Barre de navigation du bas
	•	Dock flottant en bas avec 4 icônes :
	1.	Écran (desktop)
	2.	Icône ML / chips
	3.	Globe (web)
	4.	Coquille (shell) – sélectionnée (plus en avant, ombre, fond marqué).
	•	Un bouton carré violet “stop” à gauche du dock pour arrêter l’exécution en cours (envoie un signal au backend pour stopper la commande).

7. Comportement / interactions
	•	Optimisé pour ~390×844 (iPhone), responsive.
	•	La zone du terminal scrolle si le contenu dépasse.
	•	Gestion du clavier virtuel sans masquer le dock du bas.
	•	Support du streaming de sortie (WebSocket ou SSE) pour voir les lignes du shell apparaître progressivement.

8. Intégration backend (important)
	•	Proposer une architecture simple :
	•	API pour exécuter une commande shell (ex: POST /api/shell/execute).
	•	API ou WebSocket pour streamer la sortie (stdout/stderr) et l’état de la commande (running, done, error).
	•	API pour la génération de commande avec IA (ex: POST /api/shell/generate-command avec le prompt).
	•	API pour clear / reset de la session.
	•	Décrire les types de données (JSON) échangées entre front et backend.
	•	Montrer comment le front écoute les updates en temps réel (ex : WebSocket, EventSource ou autre).
