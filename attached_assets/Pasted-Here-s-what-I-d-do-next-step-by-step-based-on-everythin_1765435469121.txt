1. Separate the two issues in your head

From the trace you pasted, there are two distinct problems:
	1.	Vite HMR WebSocket error
	•	Browser tries to connect to ws://localhost:5173
	•	That always fails on a hosted environment, because the browser isn’t on the same machine.
	2.	Replit returning 502 Bad Gateway on the public URL
	•	curl http://localhost:5000/... inside the repl works ✅
	•	But the E2E tests (and presumably your external URL) hit Replit’s proxy and get 502 ❌

The E2E tests only care about HTTP 200 from the public URL. They do not care about HMR. So:
	•	Fixing HMR = nicer dev experience
	•	Fixing 502 = required for tests to even start

I’ll cover both.

⸻

2. Fix your server binding so Replit can reach it

First, make sure your app is listening on the right interface and port:

In your server (Express/Fastify/etc)

// server/index.ts or similar
const PORT = process.env.PORT ? Number(process.env.PORT) : 5000;

app.listen(PORT, "0.0.0.0", () => {
  console.log(`Server listening on http://0.0.0.0:${PORT}`);
});

Key points:
	•	Use process.env.PORT if defined (Replit may override it).
	•	Bind to "0.0.0.0", not "localhost".

In your Replit run command

In .replit or replit.nix / “Run” configuration, make sure the command you run matches the port your server actually uses, e.g.:

npm run dev
# or
node dist/server/index.js

Not something that starts a different port than the one your code expects.

⸻

3. Make Vite HMR work on a remote host (optional but nice)

Right now, the dev client is connecting to localhost:5173 for HMR, which is correct on your local machine but wrong on Replit.

You want to tell Vite:

“Use the current page’s host, and the external HTTPS port (usually 443), not localhost:5173.”

In vite.config.ts:

import { defineConfig } from "vite";

export default defineConfig({
  server: {
    host: "0.0.0.0",
    port: 5173, // internal dev port
    hmr: {
      // client talks to the public host / HTTPS
      protocol: "wss",
      clientPort: 443,
      host: undefined, // let browser resolve to current host
    },
  },
});

Or, if you prefer to be explicit and have an env var like PUBLIC_HOST:

hmr: {
  protocol: "wss",
  clientPort: 443,
  host: process.env.PUBLIC_HOST, // e.g. "replit-clone-henri45.replit.app"
},

If you’re creating the dev server manually in server/vite-loader.ts, pass the same options there:

import { createServer as createViteServer } from "vite";

export async function createVite() {
  const vite = await createViteServer({
    server: {
      hmr: {
        protocol: "wss",
        clientPort: 443,
        host: undefined,
      },
    },
  });

  return vite;
}

If HMR is still annoying / non-critical, an even simpler fallback is:

server: {
  hmr: false, // disable HMR on Replit
}

Then you at least lose the scary WS errors.

4. To get E2E passing: serve a “production” build on a stable port

If HMR and Replit’s dev proxy are being flaky, you can:
	1.	Build the app
	2.	Serve the built assets from the same Node server on port 5000
	3.	Point tests at that

Example:

npm run build
node dist/server/index.js

And in your server, make sure you statically serve the built client:

import path from "path";
import express from "express";

const app = express();
const PORT = process.env.PORT || 5000;
const clientDist = path.join(__dirname, "..", "client-dist"); // adjust

app.use(express.static(clientDist));
app.get("*", (_req, res) => {
  res.sendFile(path.join(clientDist, "index.html"));
});

app.listen(PORT, "0.0.0.0", () => {
  console.log(`Server listening on http://0.0.0.0:${PORT}`);
});

That setup tends to be much more stable behind Replit’s proxy than a dev server + HMR.

Given your log says:

	•	Replit URL / E2E → 502 ❌

Concrete actions you can take right now:

This forces Replit’s proxy to reattach.
	2.	Check the actual public URL manually
	•	Open https://replit-clone-henri45.replit.app (or whatever your Repl URL is) in a normal browser.
	•	If that fails with 502 while curl localhost:5000 works, that’s almost certainly infra / proxy.
	3.	Try a new Repl using the same code
	•	Create a new Repl
	•	Copy package.json, server/, client/, etc.
	•	Run it there. Sometimes the new instance gets a healthy proxy.
	4.	As a last resort: deploy somewhere else (if you must pass E2E now)
	•	Render, Fly.io, Railway, etc.
	•	Anywhere that gives you a stable public URL with your Node server on 0.0.0.0:PORT.
