AUDIT COMPLET E-CODE.AI - RAPPORT DE PRODUCTION

SECTION 1 : PROBLEMES CRITIQUES SECURITE (Bloquer le déploiement)
PROBLEME #1 — Credentials de test en production
Fichier: server/index.ts ligne 936
Problème: console.log('Test user seeded (testuser@test.com / testpass123)') — les credentials de test sont seedées même en production et loguées en clair
Solution: Envelopper le seeding dans une condition if (process.env.NODE_ENV === 'development') et supprimer le console.log des credentials
PROBLEME #2 — Path Traversal faible
Fichiers: server/terminal.ts:574, server/websocket/collaborative-editing-ws.ts:347, server/routes/git.router.ts
Problème: La validation utilise if (newDir.includes('..')) — contournable par encodage URL, symlinks, ou patterns ..;
Solution: Utiliser path.resolve() + validation que le chemin résolu reste dans le répertoire de base du projet : resolvedPath.startsWith(baseDir)
PROBLEME #3 — Bypass CSRF pour Bearer Token
Fichier: server/middleware/security.ts lignes 330-349
Problème: Le CSRF est complètement sauté si le header contient Bearer — même un token invalide bypasse la protection
Solution: Valider le Bearer token (vérifier JWT) AVANT de sauter la vérification CSRF
PROBLEME #4 — Git credentials dans les URLs
Fichier: server/routes/git.router.ts lignes 19-36
Problème: Le mot de passe/token GitHub est injecté dans l'URL git (url.password = credentials.password), potentiellement logué dans les erreurs
Solution: Utiliser GIT_ASKPASS ou les credential helpers de Git. Ne jamais mettre de credentials dans les URLs
PROBLEME #5 — Device ID prédictible (Mobile)
Fichier: server/routes/mobile-sessions.router.ts ligne 200
Problème: const actualDeviceId = deviceId || ${platform}-${Date.now()} — timestamp prédictible
Solution: Utiliser crypto.randomUUID() ou crypto.randomBytes(32).toString('hex')
PROBLEME #6 — Pas de validation de domaine custom
Fichier: server/routes/deployment.ts lignes 1351-1413
Problème: Le domaine custom est sauvé sans validation DNS, sans vérification de propriété, sans sanitization
Solution: Valider le format du domaine (regex), vérifier la propriété via TXT record DNS, rate-limiter l'endpoint
PROBLEME #7 — Injection de commandes via noms de fichiers Git
Fichier: server/routes/git.router.ts ligne 224
Problème: await execa('git', ['add', ...files]) — le tableau files n'est pas validé
Solution: Valider chaque fichier contre le répertoire du projet, rejeter les noms contenant des caractères spéciaux shell
PROBLEME #8 — Sanitization XSS par regex (contournable)
Fichier: server/middleware/security.ts lignes 360-366
Problème: .replace(/<\s*\/??\s*script.*?>/gi, '') — regex contournable par encodage, cas mixtes, tags imbriqués
Solution: Remplacer par une librairie dédiée : DOMPurify côté client, sanitize-html côté serveur

Fichier: server/routes/deployment.ts lignes 1190-1244

PROBLEME #12 — Health check superficiel
Fichier: server/index.ts lignes 320-353

PROBLEME #13 — 2FA retourne 200 au lieu de 401
Fichier: server/routes/auth.router.ts lignes 284-294
Problème: Quand 2FA est requis, l'API retourne status(200) avec requires2FA: true
Solution: Retourner status(401) ou un code custom status(202) pour indiquer que l'auth est incomplète
PROBLEME #14 — Pas de limite de déploiements par utilisateur
Fichier: server/routes/deployment.ts lignes 167-235
Problème: Un utilisateur peut créer un nombre illimité de déploiements, pas de check de budget

PROBLEME #15 — Race condition sur les sessions collaboratives
Fichier: server/routes/collaboration.ts lignes 764-774
Problème: La création de session n'est pas dans une transaction — deux requêtes simultanées créent des doublons
Solution: Utiliser db.transaction() avec un ON CONFLICT DO NOTHING ou un lock optimiste
PROBLEME #16 — Pas de rate limit sur le password reset
Fichier: server/routes/auth.router.ts lignes 954-1050
Problème: Le rate limiting est logué mais la réponse est toujours success — permet l'énumération d'emails
Solution: Enforcer le rate limit (5 requêtes/heure par IP) et retourner 429 si dépassé
PROBLEME #17 — Init async non bloquante
Fichier: server/terminal.ts lignes 23-26
Problème: containerExecutor.init().catch(err => { logger.error(...) }) — l'erreur est loguée mais le serveur continue sans executor

PROBLEME #18 — Type confusion sur userId
Fichiers: server/routes/collaboration.ts:56, server/terminal.ts:104
Problème: userId est parfois string, parfois number — project.ownerId !== authResult.userId peut échouer par type confusion
Solution: Standardiser userId comme number partout. Ajouter Number(userId) à chaque comparaison
PROBLEME #19 — Hardcoded scaling limits
Fichier: server/routes/deployment.ts lignes 13-17
Problème: maxInstances: 10, maxCostPerDay: 100, cooldownPeriod: 300 — tout est hardcodé
Solution: Déplacer dans des variables d'environnement avec des defaults : SCALING_MAX_INSTANCES, SCALING_MAX_COST, etc.
PROBLEME #20 — DNS verification simulée
Fichier: server/routes/deployment.ts ligne 1459
Problème: La vérification DNS pour les domaines custom est simulée, pas réelle
Solution: Implémenter une vraie vérification DNS avec dns.resolveTxt() pour vérifier le TXT record de propriété
