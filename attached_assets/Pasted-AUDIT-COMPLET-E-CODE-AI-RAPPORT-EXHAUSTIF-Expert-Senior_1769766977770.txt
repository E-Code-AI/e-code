PROBLÈME B-03 : JSON.parse() sans try-catch dans plusieurs services
Fichiers : server/services/project-context.ts, server/services/repo-overview-service.ts, server/services/advanced-ai-service.ts
Détail : JSON.parse() peut lancer une SyntaxError si le JSON est invalide, crashant le processus.
Solution : Envelopper chaque JSON.parse() dans un try-catch ou créer un utilitaire safeJsonParse(str, fallback) :

}

PROBLÈME R-01 : Touch targets parfois trop petits
Détail : Les WCAG requièrent un minimum de 44x44px pour les cibles tactiles. Certains boutons de l'IDE (tabs, actions du file explorer) sont plus petits.

PROBLÈME R-02 : Pas de layout optimisé spécifique pour tablette
Détail : La plupart des composants ont un mode "mobile" et un mode "desktop" mais pas de mode intermédiaire pour les tablettes (768-1024px).

  /* Layout tablette : side panel réduit + éditeur plein écran */

Détail : Certains composants utilisent des valeurs en px fixes au lieu de valeurs relatives.

PROBLÈME R-04 : Orientation paysage sur téléphone — edge cases

PROBLÈME R-05 : RTL (Right-to-Left) non supporté

10. PERFORMANCE & SCALABILITÉ <a name="10-performance"></a>
PROBLÈME PF-01 : Query client cache peut grossir indéfiniment
Détail : Le cache React Query n'a pas de limite de taille configurée.
Solution : Ajouter gcTime (garbage collection) et limiter le nombre de queries cachées :

const queryClient = new QueryClient({
  defaultOptions: {
    queries: { gcTime: 1000 * 60 * 30, staleTime: 1000 * 60 * 5 }
  }
});

PROBLÈME PF-02 : Service Worker cache non purgé
Détail : Le SW cache les assets statiques mais ne purge pas les anciennes versions.
Solution : Ajouter une stratégie de nettoyage dans activate :

self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then(keys => 
      Promise.all(keys.filter(k => k !== CURRENT_CACHE).map(k => caches.delete(k)))
    )
  );
});

PROBLÈME PF-03 : localStorage/sessionStorage utilisé massivement (241+ références)
Détail : Risque de dépassement du quota localStorage (5-10MB selon le navigateur).
Solution : Migrer les données volumineuses vers IndexedDB (via idb ou localforage). Garder localStorage uniquement pour les petits tokens/préférences.

PROBLÈME PF-04 : Animations agent potentiellement coûteuses
Détail : Les animations de messages de l'agent ne sont pas throttlées et peuvent causer du jank.
Solution : Utiliser requestAnimationFrame et vérifier useReducedMotion() avant chaque animation complexe. Limiter les animations à 60fps.

PROBLÈME PF-05 : setInterval non registrés dans certains services
Détail : Certains setInterval peuvent ne pas être enregistrés dans l'interval-registry, causant des fuites mémoire.
Solution : Auditer tous les setInterval dans le backend :

grep -rn "setInterval" server/ --include="*.ts"

Et s'assurer que chacun est enregistré dans interval-registry.ts pour cleanup au shutdown.
