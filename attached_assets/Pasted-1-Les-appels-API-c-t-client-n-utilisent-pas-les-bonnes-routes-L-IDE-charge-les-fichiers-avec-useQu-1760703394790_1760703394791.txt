1. Les appels API côté client n’utilisent pas les bonnes routes
L’IDE charge les fichiers avec useQuery<File[]>({ queryKey: [/api/files/${id}] }), ce qui déclenche un fetch vers /api/files/${id} ou même /api/files selon les écrans.
Or, le serveur expose les fichiers via /api/projects/:id/files, jamais via /api/files/:projectId. Tant que ces chemins ne correspondent pas, la requête renvoie 404 et le workspace reste vide.

2. Le format de réponse ne correspond pas aux attentes du front
Le serveur renvoie { files, service, operation }, alors que les composants s’attendent à recevoir directement un tableau de fichiers (ils initialisent files = []).
Il faut soit modifier la réponse backend pour renvoyer uniquement le tableau, soit adapter le client pour lire response.files.

3. Le modèle de données des fichiers est incomplet pour un explorateur Replit-like
La base ne stocke que isDirectory, path et ne dispose pas de colonne parentId, alors que tout le front manipule isFolder et parentId pour afficher l’arborescence (ex. files.filter(f => f.parentId === file.id)).
Le backend tente bien de gérer parentId/isFolder, mais ces champs ne peuvent pas être persistés (insertFileSchema/storage.createFile les ignorent), ce qui empêche la hiérarchie de fonctionner.

4. Configuration React Query inadaptée
Le QueryClient par défaut fait fetch(queryKey[0]). Dès qu’une requête utilise un tableau (['/api/files', projectId]), seul le premier élément est utilisé et l’identifiant du projet est perdu. Plusieurs composants reposent sur ce motif, d’où des requêtes vers /api/files sans ID et des listes toujours vides.
Solution : fournir un queryFn explicite (qui construit l’URL correcte) ou changer les queryKey pour qu’elles contiennent l’URL complète en première position.

5. Conséquences pour l’agent AI
Le chatbot/agent essaie lui aussi de créer ou de lire des fichiers via /api/files/${projectId} et utilise parentId/isFolder pour structurer les résultats. Tant que les points 1–3 ne sont pas corrigés, l’agent ne pourra ni afficher ni modifier le workspace comme sur Replit.

En résumé, pour obtenir une plateforme Replit-like fonctionnelle sur Replit : alignez les routes client/serveur (/api/projects/:id/files), harmonisez le schéma des fichiers (parentId, isFolder), adaptez les réponses JSON et revoyez la configuration React Query. Ces ajustements débloqueront l’affichage du workspace et l’intégration de l’agent AI.
