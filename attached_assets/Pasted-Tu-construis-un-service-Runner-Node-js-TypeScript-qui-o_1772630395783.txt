Tu construis un service “Runner” (Node.js + TypeScript) qui orchestre des workspaces Docker long-running pour une plateforme type Replit.

Objectif MVP “workspace live” (pas un simple run) :
- 1 workspace = 1 conteneur Docker long-running basé sur l’image vibe-workspace:latest
- filesystem persistant via volume Docker par workspace
- terminal interactif via WebSocket (PTY) : /ws/workspaces/:id/terminal?token=...
- exécution de commandes via API : POST /workspaces/:id/exec (non-interactif) + streaming logs
- preview HTTP via reverse proxy : GET /preview/:id/* route vers le port 3000 du conteneur (support websockets si possible)
- API fichiers : list/read/write/mkdir/rm/rename via endpoints /fs/:id/... en utilisant le volume monté (/workspace)
- sécurité : JWT court obligatoire (Authorization Bearer token ou query token WS), non-root, cap-drop, no-new-privileges, limites CPU/RAM/PIDs, timeout sur exec, rate limiting.

Variables env runner :
- PORT=8081
- RUNNER_JWT_SECRET
- WORKSPACE_IMAGE=vibe-workspace:latest
- SANDBOX_NETWORK=sandbox_net
- DEFAULT_PREVIEW_PORT=3000
- CPU_NANO, MEMORY_MB, PIDS_LIMIT, WORKSPACE_IDLE_TTL_SEC

Endpoints à implémenter (réponse JSON claire) :
- GET /health
- POST /workspaces  body: { projectId, userId } -> { workspaceId }
- POST /workspaces/:id/start
- POST /workspaces/:id/stop
- GET  /workspaces/:id/status
- POST /workspaces/:id/exec body: { cmd, cwd, envSafe, timeoutMs } -> { runId }
- POST /workspaces/:id/exec/:runId/cancel
- WS   /ws/workspaces/:id/terminal (bidirectionnel, PTY + resize)
- WS   /ws/workspaces/:id/logs?runId=... (stdout/stderr/status)
- GET  /preview/:id/*  (proxy vers http://<container-ip>:3000)
- FS API (MVP):
  - GET /fs/:id/list?path=/
  - GET /fs/:id/read?path=...
  - PUT /fs/:id/write?path=...  body: { contentBase64 }
  - POST /fs/:id/mkdir body: { path }
  - POST /fs/:id/rm body: { path, recursive }
  - POST /fs/:id/rename body: { from, to }

Implémentation recommandée :
- dockerode pour Docker
- ws pour WebSockets
- node-pty pour PTY (terminal)
- http-proxy pour preview proxy
- express ou fastify
- rate limit (express-rate-limit) + trust proxy si derrière Caddy

Sécurité :
- conteneur non-root (user 1000)
- capDrop ALL
- noNewPrivileges true
- memory, cpuQuota/cpuPeriod (ou NanoCpus), pidsLimit
- pas de montage de /var/run/docker.sock dans les workspaces
- réseau Docker sandbox_net (internal) pour bloquer internet sortant
- logs d’audit : create/start/stop/exec

Livrables :
- code complet (runner/), package scripts, build, start
- Dockerfile du runner
- README “how to run” avec docker compose
- tests simples (smoke): create workspace, exec `node -v`, terminal echo, preview proxy check
